# Combined market presentation and bounded rendering

Shortlist and history share grouping for both sides of handicap/spread, home/away team Over, home/away team Under, match Over/Under, 1X/X2/12, draw-no-bet, winner outcomes, BTTS Yes/No and clean sheets. Periods and sports remain separate. Each fixture retains all exact selections, proof, prices and controls; options rank by original Model %, then historical floor. Family order remains stable. History filters use the same combined identities and still allow side/direction and exact-line filtering; losses remain part of dashboard cohort calculations.

Selection rules starts collapsed. Shortlist, history and fixture MarketList bodies render only while their accordion is open; previously all closed tables/proof elements were mounted. Existing per-market Show more keeps all fixtures reachable. History requests a small admin-authorized index from existing Convex metadata instead of downloading/decompressing the entire R2 catalog just to find dates. Actual selected-day history still comes from R2. The endpoint returns only the date index and reads no R2 objects; no new database record, polling or provider calls. Mobile nav preloads route code as it becomes visible.

These changes target identified rendering, transfer and navigation costs without changing model probabilities or moving bulk data to Convex. Physical-device latency across variable networks remains an acceptance check, not a universal speed guarantee.

Verification: Svelte zero errors/warnings; production build passes; 231 Node tests pass plus the new combined-history filter test independently; six route tests pass. Browser QA passes at 390px and 1440px with zero initial closed-market fixture tables, 80 fixtures reachable per test market, preserved proof download, recurrence meters, history filtering/results, adding forecast options to slip and no horizontal overflow. This demonstrates reduced initial DOM construction; it does not establish a measured universal navigation latency improvement.
